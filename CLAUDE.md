# InnerVoice — notes for agents

Document-based Mac app for audiobook narrators: opens a manuscript, finds every line, tags who speaks it with an on-device model (llama.cpp or Apple's), and builds character summaries. Read `docs/BRIEF.md`, `docs/STORIES.md`, `docs/GLOSSARY.md` (one name per idea; use it in all UI text) and `docs/DESIGN.md` before changing anything.

## Layout
- `Sources/InnerVoiceKit/` pure logic with Swift Testing tests: `Project.swift` (the book model), `Import/` (readers for docx, odt, epub, pdf, pages, rtf, html, txt, md; chapter detection), `DialogueFinder`, `RuleAttribution` (+ palette, exchange), `AI/` (prompts, grammars, model catalog + memory advice), `RevisionMerger`, `ProjectBuilder` (+ pronunciation finder), `BookIndex`.
- `Sources/InnerVoice/` the app: `Document/` (ReferenceFileDocument `.innervoice`: one zip file, `ProjectArchive` in the Kit; 0.1.0 packages still open and are saved as one file; every edit goes through `change(_:undoManager:)` for undo), `AI/` (LlamaEngine, ModelManager, TaggingController), `Views/` (ManuscriptTextView is TextKit 1 with a custom layout manager for highlights and a MarginOverlay for initials), `Export/`, `Speech/` (voices: VoiceCatalog, SpeechRenderer with an audio cache in Application Support, SpeechPlayer, casting and tone edits, Export Audio; `ModelSpeech` runs Pocket TTS, Qwen3-TTS, Chatterbox and Orpheus on MLX via the pinned mlx-audio-swift package, `VoiceModels` downloads their voice packs into Application Support/Inner Voice/Voice Models; `ElevenLabs` and `GeminiVoices` are the cloud engines), `System/` (house features: updater, sync, appearance, Dock/menu bar, ToolHUD hub, ShortcutsLens, About, Help; wired through `SystemHooks`).
- `Frameworks/llama.xcframework` is fetched by `Tools/fetch_llama.sh` (pinned b11205, not committed).

## Rules
- US spelling, "Settings", "click". Red is reserved for Who's Speaking?/Unsure; character colors come from `CharacterPalette` and never reddish.
- Never touch `NSDocumentController.shared` before launch finishes (menus included): SwiftUI must create it, or the app crashes in `createDocumentClassIfNeeded`. Use `RecentProjects`.
- Lines the narrator assigned (`source == .user`) are never changed by the AI or the rules. The same goes for tones (`toneSource == .user`) and voices (`CastVoice.source == .user`).
- Tones and voices live in the Kit: `ToneRules` + `TonePrompt` (the AI's tone pass runs inside Tag Speakers, with a per-chunk grammar that needs an answer for every line), `VoiceCasting` (profile from facts, titles and pronouns; Apple voice ages faked with pitch), `SpeechScript` (segments, narration split, pronunciations applied). Test runs play speech silently unless `INNERVOICE_SPEECH_AUDIBLE` is set.
- A project is always saved as one ordinary file: cloud folders (OneDrive) rename and replace packages under an open window, which then can't save.
- The model downloads (the tagging model and the voice packs) are the only network use besides updates and the cloud engines. Manuscripts stay on the Mac except through ElevenLabs (`Speech/ElevenLabs.swift`, eleven_v4) and Gemini TTS (`Speech/GeminiVoices.swift`, Google; request shapes in the Kit's `GeminiTTS`), the two cloud voice engines (plus Claude, below): each needs its own key (keychain) plus the narrator's yes in Settings, AND the book's own permission for that company (`cloudVoicesAllowed` for ElevenLabs, `googleVoicesAllowed` for Google; always check with `ProjectSettings.allowsCloud(engine)`, never one flag for both). `VoiceResolver` (per-engine `cloudAllowed`) and each engine's `render(allowed:)` enforce it. Never send book text anywhere else, and keep both labeled Cloud wherever they appear. The self-test checks nothing is sent without permission against `FakeElevenLabs` and `FakeGemini` (URLProtocols; `SelfTestGemini.swift` also checks a book that allowed only ElevenLabs sends nothing to Google); test runs keep the keys in memory, never the keychain.
- Apple silicon only: MLX (Pocket TTS, Qwen3-TTS, Chatterbox, Orpheus) has no Intel build. `build.sh` copies the SwiftPM resource bundles (MLX's `default.metallib`, tokenizer defaults) into Contents/Resources; without the metallib MLX can't run. Compiling needs Xcode's Metal Toolchain (`xcodebuild -downloadComponent MetalToolchain`).
- Pocket TTS (Kyutai, CC BY 4.0; `mlx-community/pocket-tts`, the MLX conversion of `kyutai/pocket-tts`, 240 MB, one repo: model.safetensors with the flow LM and the Mimi codec, tokenizer.json, config.json; about 1 GB of memory while it speaks, 0.3–0.8 s a line on Apple silicon) replaced Qwen3-TTS on 2026-11-13 (the user wanted no Chinese models then); on 2026-11-14 the user brought Qwen3-TTS back beside it ("too good to remove"), see the Qwen3-TTS rule. Chatterbox was tried first on 2026-11-13 and dropped (parts from Alibaba research); on 2026-11-14 the user asked for it back beside the others, labeled like Qwen3-TTS (see the Chatterbox rule). Pocket TTS provenance (checked 2026-11-13): model, Mimi codec and SentencePiece tokenizer are Kyutai's (Paris); the speaker conditioning is Mimi's encoder plus a projection inside the model, no separate speaker encoder; mlx-audio's loader (`Models/PocketTTS`, `MLXAudioCodecs/Mimi`) uses nothing else, and skips the config's `hf://` tokenizer path in favor of the local tokenizer.json, so nothing is fetched at load (`PocketTTSModel.fromModelDirectory`). It can't design a voice from a description: every voice is cloned from a clip (`refAudio`). Stock voices (`VoiceInfo.pocket`, voiceID "stock:<name>") clone from clips shipped in Resources/StockVoices (16-bit Apple Lossless, 24 kHz mono, 8–11 s each): Orpheus's eight voices saying `PocketClips.passage` (remake with the self-test's `APP_MAKE_STOCK_VOICES=<folder>`, then `afconvert -f WAVE -d LEI16@24000` and `afconvert -f m4af -d alac`), plus Alba (`PocketVoice.builtInID`, Pocket TTS's own default voice: alba-mackenna/casual.wav from `kyutai/tts-voices`, CC BY 4.0, converted to 24 kHz). Pocket TTS's other ready-made voices weren't added; of the ones mlx-community ships, cosette (Expresso) and jean (EARS) are non-commercial only. Credits for Kyutai, Alba MacKenna and Orpheus are in `Credits` (AboutWindow.swift, shown in About), Help › Voices & Listening › Credits and the README; CC BY needs them. Casting picks stock voices by gender and age like Apple voices (`VoiceCasting.ageAdjusted`: child +3 st and quicker, older −2 st and slower, as `choice.pitch`/`rate`); pitch (shade + age + tone) shifts the clip before cloning (`ShadeAudio`, ±2 st kept the voice with Qwen), pace, age speed and the tone's speed stretch the finished audio (`SpeechRenderer`). Pocket TTS has no emotion or speed setting, only its sampling temperature (default 0.7): `PocketDelivery` (Kit, reasoning in the comment) maps each tone to a temperature (0.5–0.95), a semitone, a speed (0.92–1.06) and a loudness; narration is always even; whispered is only softer and slower. It needs no run-on cut (short lines tested at the even and angry temperatures; the self-test checks it). Output leveled to -20 dB. `VoicePack.pinHubCache()` (Main) still sets `HF_HUB_CACHE` to the voice models folder so mlx-audio never reads or fetches into ~/.cache.
- Qwen3-TTS (engine "qwen"; Alibaba's Qwen team, Apache 2.0; `VoicePack.qwen` = mlx-community `Qwen3-TTS-12Hz-1.7B-VoiceDesign-8bit` + `-Base-8bit`, 6.2 GB, about 6 GB while it speaks), back 2026-11-14. The user asked that Settings mark it as Chinese-developed and running locally, so it's safe to use: `LocalOriginBadge` ("Developed in China · Runs on this Mac", green, with the detail text) on its Settings › Voices row, the project-type engine list and Describe a Voice; keep that label wherever Qwen3-TTS is offered, and keep the claim true: models load with `Qwen3TTSModel.fromModelDirectory` (local files only; text tokenizer and speech_tokenizer ship in the repos), the only network use is the pack download. Voices: 16 `VoiceInfo.qwenPresets` ("preset:<slug>"), "design" (`VoiceChoice.design`; casting designs one from `VoiceCasting.describe` when the book or Voice Notes describe the character, and `VoiceResolver.withNotes` adds the Voice Notes when it speaks), and "clone:<id>" (the same LocalClones recording Pocket TTS uses, spoken with its words). `QwenSamples`: VoiceDesign records `sampleText` once per (design, tone) into Voice Models/Samples, then Base clones every line from it (measured 2026-11-09: same-character similarity 0.976 vs 0.949 other); shades and the narrator's pitch shift the sample (`-shade<n>.caf`), speed is stretched after (`SpeechRenderer`). Memory (`MLXSpeech.makeRoom`): Pocket stays beside one big engine on 16 GB+, Qwen3-TTS and Orpheus together only on 32 GB+. The Qwen3 *tagging* models stay out (only the voice engine came back).
- Chatterbox (engine "chatterbox"; Resemble AI, MIT; `VoicePack.chatterbox` = `mlx-community/Chatterbox-TTS-fp16` + `mlx-community/S3TokenizerV2`, 3.2 GB, about 4 GB while it speaks), back 2026-11-14 at the user's request. Its speech tokenizer and S3Gen flow decoder come from Alibaba's CosyVoice and its speaker encoder (CAM++) from Alibaba's 3D-Speaker, so `LocalOriginBadge(engine: .chatterbox)` says "Uses parts developed in China · Runs on this Mac" (`VoiceEngine.hasChineseOrigin`) wherever it's offered. Voices: `VoiceInfo.chatterbox` = its own default voice ("stock:chatterbox", Resources/StockVoices/chatterbox.m4a, from Chatterbox Turbo's conds) + Pocket TTS's stock voices re-engined, same "stock:"/"clone:" IDs and `PocketClips` (shade + age pitch shift the clip). Tones → `ChatterboxDelivery` (exaggeration ≤ 0.8, CFG weight); `ChatterboxRunOn` cuts the made-up speech after a short line. `ChatterboxModel.fromModelDirectory` loads the S3 tokenizer through mlx-audio's default HF cache, which `pinHubCache` points at the voice models folder. Memory: under 32 GB only one of Orpheus/Qwen3-TTS/Chatterbox stays loaded. `APP_SELFTEST_GET_CHATTERBOX=1` (with APP_VOICE_MODELS) downloads it into a test folder and `chatterboxVoices` speaks every voice and tone.
- Gemini TTS (engine "gemini", Cloud, Google): Interactions API `POST v1beta/interactions` (`gemini-3.8-flash-tts` default, Flash-Lite in Settings), 30 prebuilt voices (`GeminiTTS.voices`), tone + thought + delivery hint → `speech_metadata.style`, speech-tag sounds → inline tags (`<sigh>`), `store: false`, WAV back (24 kHz). No speed setting: rate and shade are applied after (`SpeechRenderer`). Usage records seconds of audio and a cost (paid-tier prices double on 2027-01-01). Hume Octave was considered and dropped: its API shut down 2026-11-13.
- Speechify (engine "speechify", Cloud, `Speech/SpeechifyVoices.swift`, shapes in the Kit's `SpeechifyTTS`; Windows mirrors both): `POST api.speechify.ai/v1/audio/speech` with `Authorization: Bearer`, model simba-3.5, SSML input, WAV 24 kHz back (base64 `audio_data`, `billable_characters_count`), ≤ 2,000 spoken characters a request (chunks of 1,800). Voices are fetched (`GET /v1/voices?type=shared&locale=en`, paged) and the pages kept in the `speechify.voiceList` default; personal voices (clones) are never listed. Simba 3.x ignores the emotion tag, so tones are SSML prosody only (`SpeechifyTTS.prosody`); delivery hints and sounds aren't sent. Its own book permission `speechifyVoicesAllowed`. Free plan ≈ 1 request/s: 429/503 retried through `SpeechifyPace`. Export Audio estimates characters × $20/M (`SpeechifyTTS.dollarsPerMillionCharacters`, Starter rate Nov 2026). The API plan is separate from the Speechify reading app. Self-test fakes it with `FakeSpeechify`.
- Old books: 1.0.0–1.0.2 read "qwen" as Pocket TTS and moved those voices to "pocket" (`LegacyVoices`, removed 2026-11-14); books they opened keep their Pocket TTS voices, books they never opened still open with their Qwen3-TTS voices. "chatterbox" is a real engine again (the unshipped 0.4 test build used the same voice IDs); an unknown engine reads as `.mixed`, which names no voices. Remove Old Voice Files is gone (Qwen's files are live again).
- `APP_SELFTEST_VOICES=1 APP_VOICE_MODELS=<folder with mlx-audio/…>` makes the self-test speak with every installed MLX engine (`qwenVoices`: casting designs, one sample per tone, Voice Notes into the design, a shaded preset); `APP_SELFTEST_AUDIO_OUT` keeps the audio; `APP_SELFTEST_GET_POCKET=1` downloads Pocket TTS into that folder first (only with APP_VOICE_MODELS set). `pocketVoices` speaks every stock voice, Tara in every tone and as a child (pocket-voice-*, pocket-tone-*, pocket-child), checks short lines for run-on and prints the memory footprint; One Voice writes onevoice-pocket-shaded/unshaded.wav. Its word checks need Speech Recognition permission for the test build, which it hasn't had, so they print -100% and pass.
- One engine per book (2026-11-15, `Speech/EngineSwitches.swift`): `ProjectSettings.voiceEngine` is stored explicitly (nil reads as Apple Voices); new books start from `EngineSwitches.defaultEngine` (Settings › Voices › Voice Engine with no book open; with one open, `EngineChoice` changes that book only). Mix Engines is gone: `.mixed` stays in the file format, `engineInUse` never returns it, and a mixed book asks on open (`ProjectWindow`, `Project.adoptMixedVoices`). Engines aren't switched on or off anymore: local ones are offered once downloaded, cloud ones once set up. A cloud engine the book hasn't allowed stays chosen; every play, preview and export goes through `CloudGate.allows` (permission question, Don't Send default; no = nothing plays, with how to pick a local engine).
- Project types (`ProjectSettings.purpose`, `Views/ProjectType.swift`): Narration Tools hides Voices, Play, Export Audio and voice UI; Produce with AI Voices hides Index, the Teleprompter, narrators and Narrator Scripts; Pronunciations shows only for AI voices (`showsPronunciations`; they tell the AI voices how to say names). Recording is gone (2026-11-11): the Teleprompter only keeps your place (per book, per Mac, `TeleprompterPosition`); Recorded marks, retakes, pronunciation samples and Rehearse were removed from the UI, but `recorded`, `retakes` and pronunciation audio stay in the file format untouched. nil (not asked yet) shows everything; the window asks once (not in test runs). Gate new features with `project.showsVoices` / `showsNarrationTools` and `Page.isShown(in:)`, in pages, toolbars, context menus and the menu bar.
- Activity (`InnerVoiceKit/Activity.swift`, `System/Activity.swift`): per-day counts only, never book text (a self-test checks). Count at the action (assign/setTone/setVoice record kept vs changed; Tag Speakers counts lines and sets `Line.aiModel` for per-model accuracy). Test runs count in memory; snapshots seed made-up numbers. With settings sync, each Mac writes iCloud Drive/InnerVoice/Activity/<device>.json.
- Build Summaries has two parts: facts (then the "From the book:" block, `VoiceNotesFromBook`), then a voice brief per speaking character (`VoiceBriefPrompt`, "Voice brief:" block, scene partners by shared chapters, main characters first). Both blocks go through `GeneratedNotes.put`: replaced only while unedited. A third pass writes `BookCharacter.physical` (`PhysicalProfile.swift`: fields with `inferred` labels, chapter-dated changes, continuity flags) for characters with Appearance facts, through `PhysicalProfile.put` (same unedited rule via `physicalGenerated`); it's for author profiles (Export › Character Profiles), never narration. Progress for any background AI work shows in `BackgroundAIBar` (ProjectWindow top inset; the Manuscript keeps its own Tag Speakers banner); voice-model loading reports through `SpeechModelActivity`.
- ElevenLabs model (`ElevenLabsModel` in the Kit, `ElevenLabs.modelID`/`models`/`refreshModels`, Settings `ElevenLabsModelPicker`): per Mac, from GET /v1/models (credit multiplier, max length); audio tags only for eleven_v3+ (`supportsAudioTags`); the cache key adds the model unless it's eleven_v4; Export Audio credits = characters × multiplier. Voice Design stays on eleven_ttv_v3.
- Voice Notes shape Qwen3-TTS designed voices (added each time they speak) but don't change how Pocket TTS, Orpheus or Apple voices sound (say so honestly in UI and Help; the Voices page shows Describe a Voice for Qwen3-TTS, and "Voices from a Description" pointing to ElevenLabs for Pocket TTS). Casting reads them for gender, age, pitch and pace. ElevenLabs: Voice Design (`designVoice`, eleven_ttv_v3 then /v1/text-to-voice) from `VoiceDescription` (VoiceNotes.swift: narrator's own notes, then the brief, then "From the book", no headings or Contrast lines, capped at a whole line), only on the narrator's click, only for a book that allows ElevenLabs; it uses credits and a voice slot.
- Clone a Voice (`Views/CloneVoiceSheet.swift`): Book menu and Voices page in every book with voices; the sheet picks On This Mac or ElevenLabs and says what each needs. On This Mac (`Speech/LocalClones.swift`): `CloneAudio` joins and trims the recordings at 24 kHz, finds the words with on-device `SFSpeechRecognizer` (never the server; the narrator can edit them), `CloneClip` (Kit) cuts ≤ 15 s at a pause; saved in Application Support/Inner Voice/Cloned Voices (test runs: a temp folder) as `<id>.caf` + voices.json; voiceID "clone:<id>" on the pocket engine (or qwen, when the book speaks with Qwen3-TTS); `ModelSpeech` clones every line from that clip (`PocketClips`; Qwen3-TTS also uses the words). ElevenLabs (`ElevenLabs.cloneVoice`, /v1/voices/add multipart) needs `ElevenLabs.cloningOffered(for:)`: set up, book allows ElevenLabs, engine ElevenLabs or Mix Engines with it on. Nothing is sent until the rights checkbox; only the recordings and the name, never book text (self-test checks). Clones (`category` cloned/professional → `clonedIDs`, and every "clone:" voice) are listed first and never cast: every casting/Best Fits list goes through `ElevenLabs.castable`. Rename/delete in Settings › Voices › Cloned Voices. Recordings are temp files deleted when the sheet closes unless saved.
- Series (`SeriesVoices` in the Kit, `Views/SeriesVoicesSheet.swift`): another project is read with `InnerVoiceDocument.readProject` (never opened), `suggest` matches by name/alias, then a unique first name, main characters first, each target once; `apply` copies every engine's voice as `.user`, optionally Voice Notes (clearing the generated-block markers so Build Summaries keeps them), narrator voices and engine. One `change`, one Undo.
- Keychain and other per-redraw costs: `ElevenLabs.apiKey`/`consented` are cached in memory (views ask `isSetUp` through every engine check), as are Apple's voice list and the voice pack install check. Never add a keychain, disk or system-voice call to anything a view body reaches; the self-test times a redraw's voice questions (< 1 ms).
- Pauses (`PauseSettings` in SpeechScript, `Speech/Pauses.swift`): segments carry a `PauseKind`; the player and Export Audio look up `PauseSettings.current` per gap (live), after `SpeechAudio.trimmed` removes each voice's own silence. Sentence splitting makes each sentence a segment (cached per sentence). Playback speed is an AVAudioUnitTimePitch in the player only. Test runs never save pause or speed prefs.
- Every `change` rebuilds `BookIndex` and redraws all views of the book, so a text field bound to the project must be a `DraftTextField` (types into a draft, saves on a pause, Return or focus loss, one undo step); a plain TextField bound per keystroke lags on a full novel. Casting's whole-book pronoun scan is cached (`pronounCache`); keep anything per-render off whole-book scans.
- `InnerVoiceDocument` is `nonisolated` (ReferenceFileDocument); its mutation methods are `@MainActor`. @Published can't be used there: send `objectWillChange` by hand.
- Steps (`GuidedSteps` in the Kit, `Views/GuidedStepsBar.swift`): computed from the project every redraw (cheap counts only), the first step not done is current, `ProjectSettings.stepsDone` holds steps the narrator marked done or skipped (one undo step). Nothing runs until a click. Hidden with the `steps.hidden` default (View › Hide Steps); while shown, the Manuscript's own "Tag Speakers" invitation banner is left out.
- PDF paragraphs (`PDFReader.paragraphs`): a new paragraph is an indent, a short line before, a bigger gap or a size change. Lines are measured from their own page's left edge (`pageLefts`): printed books mirror their margins, and one book-wide margin lost every indent on the narrow side and ran those paragraphs together.
- Colors (`CharacterPalette` in RuleAttribution.swift): three families (masculine, feminine, neutral; pinks last, nearest the attention red). `BookCharacter.colorChosen`: true = picked, false = Automatic, nil = Automatic while it's a palette color (older projects). `recolorAutomatic` keeps fitting colors and never touches picked ones; the app runs `families` (whole-book pronoun scan, 1.4 s for a novel's cast the first time) off the main thread via `document.recolorAutomatic()` after Tag Speakers, Build Summaries and on open.
- Claude (Cloud; `AI/Claude.swift`, plan in docs/CLAUDE-PLAN.md): sends text only with a key, the narrator's yes and the book's `cloudTextAllowed`; `ClaudeTextModel` enforces all three. Before any whole-book Claude run, `ClaudeAsk.confirm` shows the estimated cost (`CostEstimator` in the Kit, never count_tokens). Book › Claude (Cloud) runs `ClaudeFeatures` (Clean Up Text, Write Chapter Recaps, Suggest Delivery Hints, Suggest Spellings); results go through `ClaudeProposalsSheet` while `reviewsCloudAI` is on and apply in one `change`. Clean Up Text re-finds lines only in edited paragraphs and never loses a `.user` line. Delivery hints (`Line.delivery`) reach ElevenLabs only. The self-test fakes Anthropic with `FakeClaude`.
- EPUB: `EpubReader` takes chapters from the book's table of contents (nav or NCX, fragment anchors) and falls back to `ChapterDetector`; `XHTMLBlocks` drops footnotes/endnotes and their markers. Export EPUB with Audio (`Export/EpubExport.swift`, gated like Export Audio) writes EPUB 3 with Media Overlays through `ReadAlongEpub` in the Kit; `SpeechSegment.source` is each segment's range in its paragraph, and `AudioExporter.write(timing:)` reports where each segment lands in the audio.
- Pronunciations, two lists only (2026-11-14, `PronunciationLists` in the Kit, rules in its comment): This Book (`Project.pronunciations`) and This Mac (`ComputerPronunciations`, JSON in the synced default `pronunciations.computer`; test runs memory only). The book's entry wins; `SpeechScript.sayings` merges through `PronunciationLists.computer` (set by the app). `InnerVoiceDocument.snapshot` saves the book's copy (`Project.computerPronunciations`, each entry's `list` = the listID it came from) so it plays the same elsewhere; on the list's own computer a copied word missing from the list is treated as deleted. `ProjectSettings.computerPronunciationsOff` turns the list off per book. Additions to This Mac go through `ComputerPronunciations.addAsking` (one Keep/Use/Cancel alert for conflicts). Import/export: `PronunciationFile` (CSV, text, JSON), same format on Windows. Pronunciations shows in Narration Tools books too. CLI: `pronunciations list` (source), `pronunciations share`, `pronunciations computer list/import/export`.
- Delete Text (`ManuscriptTextView.Coordinator.deletion`): paragraph cuts, whole chapters, and heading cuts; an emptied heading joins its text to the chapter before (the first keeps it with an empty title, shown as "Opening").

## Build and check
- `./build.sh --debug` → `.build/app/InnerVoice.app` (Developer ID, hardened runtime). `--install` replaces /Applications (quits the running copy).
- `swift test` — Kit tests, including real files made with textutil, ditto and CoreGraphics.
- `tools/selftest.sh` — in-app checks on the sample book (SeedData). `APP_SELFTEST_MODEL=<gguf>` also tags the sample with a real model and prints a score (Gemma 4 E2B: 27/28 in 18 s).
- `tools/snap.sh` — light and dark PNGs of every page, popover, sheet and Settings tab in /tmp/InnerVoice-shots. Look at them after UI changes.
- Test runs (APP_SNAPSHOT, --selftest, APP_STORE) start no menu bar item, sync, updater or quit question, and never save a project.
- Never capture the live screen; snapshot mode captures only its own windows.
- Agent CLI: drive the app with `innervoice` (the app binary; `Sources/InnerVoice/Agent/`, `Main.swift`). See `.claude/skills/innervoice/SKILL.md`. Commands find windows through `OpenProjects` (registered by ProjectWindow) and edit with the window's undo manager. Test with a Debug build and `APP_STORE=/tmp/iv-cli INNERVOICE_DEMO=1` (sample book; /tmp projects only; stop it with `kill <its pid>` (SIGTERM closes it without saving), never `pkill -x InnerVoice`: the person's own copy has the same name); `~/.claude/skills/agent-cli/scripts/check-agent-cli.sh <binary>` with `INNERVOICE_DEMO=1` prints PASS agent CLI.
- innervoice:// links (`AgentLink` in the Kit, `Agent/AgentLinks.swift`): the words name an agent command and its positional params, the query its options; only `open`, `lines reveal` and `projects open` (they only show things), path params absolute. An Apple Event handler installed in applicationWillFinishLaunching; links that arrive earlier wait for launch (they reach NSDocumentController). A link launch shows no SwiftUI window, so `AppState.showStart` falls back to the Window menu item; the refusal alert is a sheet (an app-modal alert would stall the agent socket). Test with `open -a .build/app/InnerVoice.app "innervoice://…"` (plain `open` reaches the person's own copy). Same rules as Windows' `AgentUrl`.
- Release: `./release.sh` (see the script; version rules in the user's memory). Don't release or push without the user's OK.
