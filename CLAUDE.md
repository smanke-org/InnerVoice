# InnerVoice — notes for agents

Document-based Mac app for audiobook narrators: opens a manuscript, finds every line, tags who speaks it with an on-device model (llama.cpp or Apple's), and builds character summaries. Read `docs/BRIEF.md`, `docs/STORIES.md`, `docs/GLOSSARY.md` (one name per idea; use it in all UI text) and `docs/DESIGN.md` before changing anything.

## Layout
- `Sources/InnerVoiceKit/` pure logic with Swift Testing tests: `Project.swift` (the book model), `Import/` (readers for docx, odt, epub, pdf, pages, rtf, html, txt, md; chapter detection), `DialogueFinder`, `RuleAttribution` (+ palette, exchange), `AI/` (prompts, grammars, model catalog + memory advice), `RevisionMerger`, `ProjectBuilder` (+ pronunciation finder), `BookIndex`.
- `Sources/InnerVoice/` the app: `Document/` (ReferenceFileDocument `.innervoice`: one zip file, `ProjectArchive` in the Kit; 0.1.0 packages still open and are saved as one file; every edit goes through `change(_:undoManager:)` for undo), `AI/` (LlamaEngine, ModelManager, TaggingController), `Views/` (ManuscriptTextView is TextKit 1 with a custom layout manager for highlights and a MarginOverlay for initials), `Export/`, `Speech/` (voices: VoiceCatalog, SpeechRenderer with an audio cache in Application Support, SpeechPlayer, casting and tone edits, Export Audio; `ModelSpeech` runs Qwen3-TTS and Orpheus on MLX via the pinned mlx-audio-swift package, `VoiceModels` downloads their voice packs into Application Support/Inner Voice/Voice Models), `System/` (house features: updater, sync, appearance, Dock/menu bar, ToolHUD hub, ShortcutsLens, About, Help; wired through `SystemHooks`).
- `Frameworks/llama.xcframework` is fetched by `Tools/fetch_llama.sh` (pinned b11205, not committed).

## Rules
- US spelling, "Settings", "click". Red is reserved for Who's Speaking?/Unsure; character colors come from `CharacterPalette` and never reddish.
- Never touch `NSDocumentController.shared` before launch finishes (menus included): SwiftUI must create it, or the app crashes in `createDocumentClassIfNeeded`. Use `RecentProjects`.
- Lines the narrator assigned (`source == .user`) are never changed by the AI or the rules. The same goes for tones (`toneSource == .user`) and voices (`CastVoice.source == .user`).
- Tones and voices live in the Kit: `ToneRules` + `TonePrompt` (the AI's tone pass runs inside Tag Speakers, with a per-chunk grammar that needs an answer for every line), `VoiceCasting` (profile from facts, titles and pronouns; Apple voice ages faked with pitch), `SpeechScript` (segments, narration split, pronunciations applied). Test runs play speech silently unless `INNERVOICE_SPEECH_AUDIBLE` is set.
- A project is always saved as one ordinary file: cloud folders (OneDrive) rename and replace packages under an open window, which then can't save.
- The model downloads (the tagging model and the voice packs) are the only network use besides updates and ElevenLabs. Manuscripts stay on the Mac except through ElevenLabs (`Speech/ElevenLabs.swift`, eleven_v4, the one cloud engine): it needs a key (keychain) plus the narrator's yes in Settings, AND the book's own `cloudVoicesAllowed`; `VoiceResolver` and `ElevenLabs.render(allowed:)` both enforce it. Never send book text anywhere else, and keep ElevenLabs labeled Cloud wherever it appears. The self-test checks nothing is sent without permission against `FakeElevenLabs` (a URLProtocol); test runs keep the key in memory, never the keychain.
- Apple silicon only: MLX (Qwen3-TTS, Orpheus) has no Intel build. `build.sh` copies the SwiftPM resource bundles (MLX's `default.metallib`, tokenizer defaults) into Contents/Resources; without the metallib MLX can't run. Compiling needs Xcode's Metal Toolchain (`xcodebuild -downloadComponent MetalToolchain`).
- Qwen3-TTS: the VoiceDesign model records a voice sample per (description, tone), kept in Voice Models/Samples; the Base model clones every line from it. Designing each line separately drifts (measured with the speaker encoder: same-character similarity fell to other-character levels). Model output is leveled to -20 dB.
- `APP_SELFTEST_VOICES=1 APP_VOICE_MODELS=<folder with mlx-audio/…>` makes the self-test speak with both engines; `APP_SELFTEST_AUDIO_OUT` keeps the audio.
- Project types (`ProjectSettings.purpose`, `Views/ProjectType.swift`): Narration Tools hides Voices, Play, Export Audio and voice UI; Produce with AI Voices hides Index, the Teleprompter, narrators and Narrator Scripts; Pronunciations shows only for AI voices (`showsPronunciations`; they tell the AI voices how to say names). Recording is gone (2026-11-11): the Teleprompter only keeps your place (per book, per Mac, `TeleprompterPosition`); Recorded marks, retakes, pronunciation samples and Rehearse were removed from the UI, but `recorded`, `retakes` and pronunciation audio stay in the file format untouched. nil (not asked yet) shows everything; the window asks once (not in test runs). Gate new features with `project.showsVoices` / `showsNarrationTools` and `Page.isShown(in:)`, in pages, toolbars, context menus and the menu bar.
- Activity (`InnerVoiceKit/Activity.swift`, `System/Activity.swift`): per-day counts only, never book text (a self-test checks). Count at the action (assign/setTone/setVoice record kept vs changed; Tag Speakers counts lines and sets `Line.aiModel` for per-model accuracy). Test runs count in memory; snapshots seed made-up numbers. With settings sync, each Mac writes iCloud Drive/InnerVoice/Activity/<device>.json.
- Build Summaries has two parts: facts (then the "From the book:" block, `VoiceNotesFromBook`), then a voice brief per speaking character (`VoiceBriefPrompt`, "Voice brief:" block, scene partners by shared chapters, main characters first). Both blocks go through `GeneratedNotes.put`: replaced only while unedited. Progress for any background AI work shows in `BackgroundAIBar` (ProjectWindow top inset; the Manuscript keeps its own Tag Speakers banner); voice-model loading reports through `SpeechModelActivity`.
- Voice Notes reach the voice models that take a description (`VoiceDescription` in VoiceNotes.swift: narrator's own notes, then the brief, then "From the book", no headings or Contrast lines, capped at a whole line). Qwen3-TTS: `VoiceResolver.withNotes` adds them to `voiceID == "design"` voices at speaking time (not stored, so edits apply; presets untouched), and casting designs a voice for any character with notes. ElevenLabs: Voice Design (`designVoice`, eleven_ttv_v3 then /v1/text-to-voice) only on the narrator's click, only for a book that allows ElevenLabs; it uses credits and a voice slot. Orpheus and Apple can't take a description.
- Clone a Voice (`Views/CloneVoiceSheet.swift`, `ElevenLabs.cloneVoice`, /v1/voices/add multipart): offered (Book menu, Voices page) only when `ElevenLabs.cloningOffered(for:)`: set up, book allows ElevenLabs, engine ElevenLabs or Mix Engines with it on. Nothing is sent until the rights checkbox; only the recordings and the name, never book text (self-test checks). Clones (`category` cloned/professional → `clonedIDs`) are listed first and never cast: every casting/Best Fits list goes through `ElevenLabs.castable`. Rename/delete in Settings › Voices › Cloned Voices. Recordings are temp files deleted when the sheet closes unless saved.
- Series (`SeriesVoices` in the Kit, `Views/SeriesVoicesSheet.swift`): another project is read with `InnerVoiceDocument.readProject` (never opened), `suggest` matches by name/alias, then a unique first name, main characters first, each target once; `apply` copies every engine's voice as `.user`, optionally Voice Notes (clearing the generated-block markers so Build Summaries keeps them), narrator voices and engine. One `change`, one Undo.
- Keychain and other per-redraw costs: `ElevenLabs.apiKey`/`consented` are cached in memory (views ask `isSetUp` through every engine check), as are Apple's voice list and the voice pack install check. Never add a keychain, disk or system-voice call to anything a view body reaches; the self-test times a redraw's voice questions (< 1 ms).
- Pauses (`PauseSettings` in SpeechScript, `Speech/Pauses.swift`): segments carry a `PauseKind`; the player and Export Audio look up `PauseSettings.current` per gap (live), after `SpeechAudio.trimmed` removes each voice's own silence. Sentence splitting makes each sentence a segment (cached per sentence). Playback speed is an AVAudioUnitTimePitch in the player only. Test runs never save pause or speed prefs.
- Every `change` rebuilds `BookIndex` and redraws all views of the book, so a text field bound to the project must be a `DraftTextField` (types into a draft, saves on a pause, Return or focus loss, one undo step); a plain TextField bound per keystroke lags on a full novel. Casting's whole-book pronoun scan is cached (`pronounCache`); keep anything per-render off whole-book scans.
- `InnerVoiceDocument` is `nonisolated` (ReferenceFileDocument); its mutation methods are `@MainActor`. @Published can't be used there: send `objectWillChange` by hand.
- Steps (`GuidedSteps` in the Kit, `Views/GuidedStepsBar.swift`): computed from the project every redraw (cheap counts only), the first step not done is current, `ProjectSettings.stepsDone` holds steps the narrator marked done or skipped (one undo step). Nothing runs until a click. Hidden with the `steps.hidden` default (View › Hide Steps); while shown, the Manuscript's own "Tag Speakers" invitation banner is left out.
- PDF paragraphs (`PDFReader.paragraphs`): a new paragraph is an indent, a short line before, a bigger gap or a size change. Lines are measured from their own page's left edge (`pageLefts`): printed books mirror their margins, and one book-wide margin lost every indent on the narrow side and ran those paragraphs together.
- Colors (`CharacterPalette` in RuleAttribution.swift): three families (masculine, feminine, neutral; pinks last, nearest the attention red). `BookCharacter.colorChosen`: true = picked, false = Automatic, nil = Automatic while it's a palette color (older projects). `recolorAutomatic` keeps fitting colors and never touches picked ones; the app runs `families` (whole-book pronoun scan, 1.4 s for a novel's cast the first time) off the main thread via `document.recolorAutomatic()` after Tag Speakers, Build Summaries and on open.
- Delete Text (`ManuscriptTextView.Coordinator.deletion`): paragraph cuts, whole chapters, and heading cuts; an emptied heading joins its text to the chapter before (the first keeps it with an empty title, shown as "Opening").

## Build and check
- `./build.sh --debug` → `.build/app/InnerVoice.app` (Developer ID, hardened runtime). `--install` replaces /Applications (quits the running copy).
- `swift test` — Kit tests, including real files made with textutil, ditto and CoreGraphics.
- `tools/selftest.sh` — in-app checks on the sample book (SeedData). `APP_SELFTEST_MODEL=<gguf>` also tags the sample with a real model and prints a score (Gemma 4 E2B: 27/28 in 18 s).
- `tools/snap.sh` — light and dark PNGs of every page, popover, sheet and Settings tab in /tmp/InnerVoice-shots. Look at them after UI changes.
- Test runs (APP_SNAPSHOT, --selftest, APP_STORE) start no menu bar item, sync, updater or quit question, and never save a project.
- Never capture the live screen; snapshot mode captures only its own windows.
- Agent CLI: drive the app with `innervoice` (the app binary; `Sources/InnerVoice/Agent/`, `Main.swift`). See `.claude/skills/innervoice/SKILL.md`. Commands find windows through `OpenProjects` (registered by ProjectWindow) and edit with the window's undo manager. Test with a Debug build and `APP_STORE=/tmp/iv-cli INNERVOICE_DEMO=1` (sample book; /tmp projects only; stop it with `kill <its pid>` (SIGTERM closes it without saving), never `pkill -x InnerVoice`: the person's own copy has the same name); `~/.claude/skills/agent-cli/scripts/check-agent-cli.sh <binary>` with `INNERVOICE_DEMO=1` prints PASS agent CLI.
- Release: `./release.sh` (see the script; version rules in the user's memory). Don't release or push without the user's OK.
